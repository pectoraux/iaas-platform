# ACR-003 — Extension Stack Architecture

Status: `DRAFT`

Governing Architecture: `IAAS-GOV-ARCH-1` (FROZEN)

Current Domain Architecture: `IAAS-DOM-ARCH-3` (FROZEN)

Proposed Domain Architecture: `IAAS-DOM-ARCH-4` (not yet approved)

Requested By: Chief Architect

## Purpose

Define and, if approved, freeze the generic Extension Stack corresponding to historical `DOM-P04`: `Extension`, `ExtensionRegistry`, and `ExtensionRuntime`.

This request exists because DOM-P04 is explicitly FUTURE/OPEN/RESEARCH in V3. No implementation may promote it merely because the platform is now ready to address the next future primitive.

## Proposed Scope

The proposed architecture must establish:

1. `Extension` as a generic capability/plugin contract, not a vertical feature.
2. `ExtensionRegistry` as discovery/catalog/version/lifecycle authority without executing extensions.
3. `ExtensionRuntime` as execution/isolation authority without owning catalog state.
4. Explicit tenant isolation and ownership boundaries.
5. Explicit capability declaration and dependency metadata.
6. Explicit extension lifecycle states and failure semantics.
7. Explicit anti-dependencies from extensions to vertical, EconomicPipeline, Route/Transport, RuntimeRegistry, and kernel implementation.
8. Explicit security/isolation boundary without prematurely selecting WASM, container, or native technology.
9. Compatibility with the existing Transform Stack without conflating Transform and Extension responsibilities.
10. No marketplace, SDK, licensing, or concrete extension implementation in the architecture-freeze slice.

## Non-Goals

This ACR does not authorize:

- Extension production implementation.
- Sandbox technology selection.
- Marketplace implementation.
- SDK/API implementation.
- Concrete extension implementations.
- Economic attribution of extensions.
- New Prisma schema unless independently required and approved later.

## Architectural Questions

The architecture review must resolve:

- Extension identity and versioning.
- Capability declaration and compatibility.
- Dependency graph semantics.
- Registry/runtime responsibility split.
- Lifecycle and revocation semantics.
- Isolation/security contract.
- Resource/cost limits.
- Failure and recovery semantics.
- Provenance and observability boundaries.
- Relationship to TransformRegistry/TransformRuntime.

## Promotion Rule

DOM-P04 may move from FUTURE/OPEN/RESEARCH to FROZEN-CONTRACT only after:

1. this ACR is approved;
2. a new domain architecture version is produced;
3. the new architecture is frozen;
4. acceptance criteria and regression protection are defined.

No production implementation is authorized by this ACR alone.
