# ACR-001 — Promote VerifiedEvidenceContext into the Domain Architecture

- ACR-ID: `ACR-001`
- Status: `APPROVED`
- Requested by: Chief Architect
- Affected Architecture Version: `IAAS-DOM-ARCH-1`
- New Architecture Version: `IAAS-DOM-ARCH-2`
- Affected Requirements: `DOM-P01`, economic evidence/verification boundary
- Affected Work Item: `WORK-003`

## Current Rule

The economic pipeline currently accepts a VPP-specific pre-pipeline pattern in which `eventId` and `attestationId` are pre-populated on checkpoint state after vertical-specific evidence and verification.

## Problem / Evidence

`docs/architecture/ARCHITECTURE-CONSTITUTION.md` §6 explicitly identifies a future generic `VerifiedEvidenceContext` as the intended evolution. The current pattern is safe because durable Event/Attestation records remain the source of truth, but the transport of already-verified evidence is represented by a vertical-specific convention rather than a generic contract.

This creates an avoidable coupling between vertical adapters and the generic economic pipeline and makes the pre-validated-input boundary implicit.

## Proposed Change

Promote `VerifiedEvidenceContext` to a frozen generic domain contract in `IAAS-DOM-ARCH-2`.

The contract MUST:

1. represent already-verified economic evidence without owning or duplicating durable Event/Attestation records;
2. reference authoritative durable identifiers (`eventId`, `attestationId`) and their deterministic identity/provenance;
3. carry the verification policy/version that produced the attestation;
4. be immutable after construction;
5. be generic and vertical-neutral;
6. be tenant/network scoped where the underlying durable records are scoped;
7. be accepted by the generic economic pipeline as the explicit pre-validated-input boundary;
8. preserve the rule that durable PostgreSQL Event/Attestation records remain the source of truth;
9. preserve reconciliation validation of referenced durable identities and stale/NULL recovery;
10. allow verticals to produce the context without making the generic pipeline import any vertical service.

`VerifiedEvidenceContext` MUST NOT become a new economic primitive, ledger record, or replacement for Event/VerificationResult/Attestation.

## Alternatives Considered

### Keep vertical-specific checkpoint pre-population
Rejected: preserves unnecessary vertical coupling and keeps the generic pre-validated-input boundary implicit.

### Replace Event/Attestation with VerifiedEvidenceContext
Rejected: violates the evidence boundary and durable-source-of-truth rule.

### Put VerifiedEvidenceContext in the kernel
Rejected: it belongs to the evidence/economic boundary and does not require kernel ownership.

## Compatibility / Migration Impact

Existing durable Event, VerificationResult, and Attestation records remain unchanged. Existing reconciliation behavior remains authoritative. VPP behavior is migrated behind the new generic context boundary without changing its domain-specific baseline logic.

## Verification Impact

Add static architecture checks proving the context remains vertical-neutral and is not imported by the generic pipeline from any vertical. Add unit/integration tests proving durable IDs are validated and stale/invalid references are rejected or recovered according to existing reconciliation rules.

## Decision

**APPROVED** by the Chief Architect.

This ACR freezes the architectural decision in `IAAS-DOM-ARCH-2`. Implementation is delegated to `WORK-003` only after the new architecture version is registered and frozen.
