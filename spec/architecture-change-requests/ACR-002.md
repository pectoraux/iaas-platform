# ACR-002 — Promote the Transform Stack Boundary

Status: **APPROVED**

Approved by: Chief Architect

Predecessor domain architecture: `IAAS-DOM-ARCH-2` (FROZEN)

Proposed next domain architecture: `IAAS-DOM-ARCH-3` (to be frozen by WORK-009)

## Decision

Promote the currently FUTURE TransformRegistry + TransformRuntime boundary into the next domain architecture version without implementing either component in this Work Item.

## Scope

The promoted contract is strictly:

```text
Transform
   ↓
TransformRegistry
   ↓
TransformRuntime
   ↓
TransformRecord
```

The architecture must define:

- generic Transform identity and semantic version;
- registry catalog responsibilities: discovery, version compatibility, certification/revocation metadata;
- runtime responsibilities: execute/reverse/estimateCost/verify;
- TransformRecord as immutable provenance output, never an executable registry or runtime;
- service-layer ownership, not kernel ownership;
- tenant isolation and authorization boundaries;
- deterministic input/output hash verification;
- idempotency and failure semantics;
- vertical neutrality;
- no coupling to Route, TransportExecution, DeliveryConfirmation, EconomicPipeline, RuntimeRegistry, or vertical services except through explicit future contracts;
- PostgreSQL as the durable source of registry metadata/provenance where persistence is required.

## Non-goals

This ACR does not authorize production implementation, marketplace, SDK, extension sandbox technology, pricing, settlement, cryptographic-signature infrastructure, or arbitrary transform plugins.

## Evidence Basis

- `docs/architecture/PHASE-14F-TRANSFORM-RECORD-CONTRACT.md`
- `IAAS-DOM-ARCH-2` inherited architecture
- verified `TransformRecord` implementation and tests
- existing data-plane anti-dependency rules

## Required Outcome

WORK-009 must produce and freeze `IAAS-DOM-ARCH-3`. No implementation Work Item for TransformRegistry/TransformRuntime may become eligible until WORK-009 is VERIFIED.
